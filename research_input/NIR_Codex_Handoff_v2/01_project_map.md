# Карта всей проделанной работы НИР: материалы, статус и автономная передача Codex (v2.0)

**Дата:** 04.11.2026. **Тема:** «Методы обучения ансамблей деревьев решений, устойчивых к сдвигу распределения табличных данных». **Объект:** RF и GBDT × классификация/регрессия. **Постановка:** multi-source, source-only DG. **Задача пакета:** без потери контекста перейти от литературного исследования к сквозным воспроизводимым экспериментам, включая реализацию Meta-forests и научный отчёт.

## 3. Статус методов для реального стенда

| Метод | RF/GBDT × задача | Научно известен | Успешно запущен нами? | Действие |
|---|---|---|---|---|
| RF, Extra Trees | RF, К/Р | Да | **Нет** | Первые baseline в P1 |
| HistGBDT, XGBoost, LightGBM, CatBoost | GBDT, К/Р (по конкретным API) | Да | **Нет** | Проверить пакеты, парные baseline |
| IRF | RF, К/Р | Да | **Нет** | Полные формулы и код, возможно независимая реализация |
| CRF | RF, К | Да | **Нет** | R-репозиторий и зависимости |
| **Meta-forests** | RF, К | Да | **Нет** | **Обязательная попытка полного воспроизведения:** проверить оригинальные формулы, при отсутствии кода реализовать и протестировать полноценный метаансамбль; честная маркировка неоднозначностей |
| MaxRM-RF | RF, Р | Да | **Нет** | Авторский fork adaXT, posthoc и варианты |
| Era Splitting | GBDT, Р | Да | **Нет** | `erasplit`, `fit(X,y,eras)`, paired baseline |
| Anchor Boosting | GBDT, К/Р | Да | **Нет** | Source-only `fit(X,y,Z)` и paired LightGBM baseline |
| Time Robust Forest | RF, К; Р только API | Да | **Нет** | Temporal source-only smoke |
| MixMax | GBDT, К | Смежный robust-метод | **Нет** | Дополнительный source-only DG эксперимент |
| Tree DRO | GBDT, К; Р требует матем. коррекции | Смежная робастность | **Нет** | Не считать готовым регрессионным методом |

`К` = классификация; `Р` = регрессия. Научная постановка, наличие репозитория и успешная установка/воспроизведение — **три разные вещи**.

## 4. Что уже подтверждено и где доверять больше

1. **IRF regression существует** — подтверждение в статье AAAI и `context/10_consistency_audit.md`. Не опираться на противоположную строку последнего поискового обзора.
2. **Era Splitting:** регрессионный API; бинарные опубликованные эксперименты не равны самостоятельному API-классификатору.
3. **Anchor Boosting:** можно использовать DG source-only; нельзя использовать refit на target и переносить такие числа в DG.
4. **Shifts Weather:** официальный полный массив — 10M, 123 метеопризнака, температура + классификация осадков. Не путать полный массив и отдельную canonical source subset.
5. **TabReD:** подготовленные временные split не дают гарантии наличия source environments и target-blind preprocessing — нужен P0.
6. **Сравнительная матрица шести:** вторичный обзор по шести более детальным отчётам; перед точной реализацией/цитированием возвращаться к полным статьям и авторскому коду.

## 5. В какой последовательности использовать материалы

- **Для научного объяснения:** сначала `context/06_method_catalog_v1.md`, потом `context/07_six_methods_comparison.md`, `context/08_additional_methods.docx`; за конкретными формулами — к оригинальным научным публикациям.
- **Для выбора датасета:** `context/11_dataset_report_digest.md`, затем официальные репозитории и обязательный P0 data audit.
- **Для устранения противоречий:** `context/10_consistency_audit.md` имеет приоритет над некорректными строками старых поисковых итераций.
- **Для кодирования:** `03_codex_prompt.md` → `02_experiment_protocol.md` → `06_method_reproduction.md` → `04_experiment_config.yaml` → `07_outputs_and_quality.md` → `05_open_decisions.md`.
- **Для отчёта НИР:** обзор литературы + итоговая классификация + строгий DG-протокол + собственные экспериментальные результаты после P3. Не представлять опубликованные показатели как собственные.

## 6. Что требуется получить от Codex (самостоятельно, если нет внешних блокеров)

1. `data_audit.md`: доступные данные, естественные environment IDs, shape/source groups, source-only feature construction, leakage risks.
2. `method_audit.md`: реальные версии, запускаемые методы, интерфейсы, baseline-equivalence и лицензии.
3. `readiness.md`: какие 4 направления исполнимы, какие блокеры и честный объём pilot/final.
4. `source_cv_metrics.csv`: пилот **на исходных средах**, без target метрик.
5. `preregistration.md`: самостоятельно замороженный протокол P2 с обоснованиями и хешем до target.
6. Реальный репозиторий с кодом шести методов/статусами blocked, unit tests, source CV, полной допустимой серией target и `reports/` с таблицами, графиками и текстом обсуждения.
7. Подробный `docs/methods/meta_forests_replication.md` и тесты Meta-forests, отличающие оригинальную реализацию от интерпретации.

**Основной смысл:** широкая НИР подготовлена к самостоятельной реализации и научному эксперименту. Codex проверяет первоисточники, реализует все шесть центральных методов (включая Meta-forests), затем сам доводит доступные корректные ветви через P0–P4. Никаких обещаний успеха без выполненного кода/метрик и никаких target-driven решений.
