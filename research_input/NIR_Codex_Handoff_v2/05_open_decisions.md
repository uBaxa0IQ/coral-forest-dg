Это **не список вопросов к пользователю**. Все пункты, разрешимые по первоисточникам, source-данным, тестам и доступным ресурсам, Codex закрывает **самостоятельно**. Блокер одной модели не останавливает остальные ветви.

## Автономный переход P0 → P4

- **P0 (источники/данные/пакеты):** все шесть методов получили задачу научной проверки, изоляция target протестирована, доступные source domains проверены. Не нужно полного успеха каждого метода, чтобы запускать независимые ветви.
- **P1 (source-only пилоты):** tests проходят, baselines и работающие специализированные методы возвращают predictions на исходных данных, оценены CPU/RAM и выполнимость.
- **P2 (freeze):** Codex сам до обращения к target сохраняет `preregistration.md`, `experiment_manifest.csv`, конкретные source/target IDs, метрики/HPO/seeds, model status и hash. Если нет 100% готовности отдельных методов, зафиксировать это и **продолжить валидные ветви**, а не ждать пользовательского approve.
- **P3 (финал):** одна предзаданная серия target-evaluation, без target-guided изменений. Если target test оказался недоступным, оставить honest blocked вместо фиктивных чисел.
- **P4 (анализ):** таблицы, фигуры, сравнение с paired baselines, отрицательные результаты, независимые единицы статистики, ограничения и оформляемый текст НИР.

## Решения, на которые дана свобода

Выбор кода, контейнеров, ускорения, preprocessing, альтернативных datasets, разумного числа folds/seeds и бюджета, исправление несовместимостей, определение source environments и критериев исключения малых сред — **всё разрешено до freeze**, если основано только на исходных данных/первичных источниках, записано до target и не искажает исходный метод.

**Не требуется дополнительное согласование после каждого gate.** Остановиться и спросить пользователя нужно лишь для реального внешнего разрешения (credentialed data, платные вычисления, лицензирование, принципиально недоопределённый алгоритм, невозможность обеспечить строгую DG).

## Требуемые статусы завершения

Для каждой из шести работ и её поддерживаемых task types: `exact_author_code`, `verified_port`, `independent_reimplementation`, `independent_interpretation`, `blocked_unverified` + доказательство. Нужна **отдельная строка для Meta-forests**, даже если результат blocked. Все методы/данные, отсутствующие в конечных таблицах, должны быть объяснены в `reports/limitations.md`.
