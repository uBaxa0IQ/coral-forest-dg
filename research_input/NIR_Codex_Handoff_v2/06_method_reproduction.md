# Верификация и воспроизведение методов — обязательный исследовательский контракт

## Уровни достоверности

Для каждой пары **метод × задача × датасет** присваивать один статус:

- `exact_author_code`: использован оригинальный код/версия с подтверждённой конфигурацией;
- `verified_port`: код перенесён на другой API/версию с тестами эквивалентности ключевых формул и результатов;
- `independent_reimplementation`: самостоятельно реализован метод **строго по первоисточнику** с проверкой формул, тестами и известными расхождениями;
- `independent_interpretation`: научно мотивированная трактовка неоднозначной публикации, **не точная репликация**;
- `baseline_only`: обычная модель без специальной DG-механики;
- `blocked_unverified`: научно или технически недопустимо заявлять запуск воспроизведённого метода.

Указанный статус обязательно сохранять в `reports/method_matrix.csv` и metadata каждого run. Научный вывод строить с учётом уровня достоверности. Для каждого метода нужны ссылки на публикацию/версию PDF, секции формул, git commit/release исходников, тип задачи, лицензия, версия зависимостей, роль доменных меток, smoke-тест, unit-тест механизма, baseline и ограничения.

## Обязательное ядро — 6 методов

| Метод | Где ожидается | Обязательная попытка | Первичные контрольные вопросы |
|---|---|---|---|
| **IRF** | RF классификация **и регрессия** | Прочитать AAAI 2024, восстановить оба split penalty, bootstrap по средам и сглаживание; поиск оригинального кода, при необходимости независимый RF | Правильная классификация/regression penalties, направление критерия, поведение при пустых группах, согласование с опубликованной синтетикой |
| **Constrained RF** | RF классификация | Найти UAI 2026/PMLR PDF, appendix, R-реализацию, тестировать entropy/MI objective | Корректно ли учтены `H(Y|leaf)`, `I(Y;Z|leaf)` и `H(Z|leaf)`, нет ли перепутанных знаков и тривиального смешения доменов |
| **Meta-forests** | RF классификация | **Полное воспроизведение обязательно к попытке**; сначала официальный код, иначе реализовать оригинальную meta-learning/MMD/forest aggregation процедуру | Правильное исключение source-domains для meta-test, MMD, точные веса, маскирование признаков, число обучаемых лесов, target-blind model selection |
| **MaxRM-RF** | RF регрессия | Проверить `adaXT`/репозиторий; реализовать как минимум `posthoc`, затем local/global/weighting если корректно и выполнимо | Оптимизация максимума **source** риска; posthoc leaf matrix; distinction MSE/NRW/regret; локальная vs ансамблевая оптимизация |
| **Era Splitting** | GBDT регрессия | Проверить `erasplit`, mean/Boltzmann/Directional split gains и baseline того же движка | Era-wise gain, ограничения на source coverage, знак и масштабы параметров, отсутствие использования будущей era |
| **Anchor Boosting** | GBDT регрессия и бинарная классификация | Проверить пакет, source-only anchors, γ, градиенты и листовую переоптимизацию, baseline-эквивалентность | Регрессионный vs бинарный objective; `γ=1` baseline; **не применять DA/refit по target** |

### Meta-forests: отдельный обязательный рабочий пакет

1. **Оригинальная публикация.** Найти *Meta-forests: Domain generalization on random forests with meta-learning*, авторов, PDF ACML/PMLR и supplement. Проверить фактические схемы обучения/meta-test и выбор гиперпараметров. Приложенные обзоры могут содержать неточную или неполную формулу весов.
2. **Репозитории.** Проверить официальный код авторов, supplementary archives, release, цитирующие проекты. Ссылаться только на проверенное происхождение; не выдавать сторонний код за официальный.
3. **Алгоритм.** Выделить отдельно (а) список source environments, (б) pseudo-meta-test из source, (в) несколько RF и рандомизацию признаков, (г) компонент transfer accuracy, (д) MMD features между source environments, (е) итоговые веса ансамбля. **Настоящий target никак не участвует в этих компонентах.**
4. **Математическая спецификация.** В `docs/methods/meta_forests_math.md` привести оригинальные формулы и notation map; заполнить `confirmed / ambiguous / not stated`, отметить непроверенные kernel bandwidth, mask policy, random-feature choices, forest weights, normalization, hyperparameter selection.
5. **Реализация.** Если полная формула раскрыта — реализовать `MetaForestsClassifier` с явным `fit(X,y,environments)` и `predict_proba/predict`, детерминированным seed, сериализацией и явным списком forest members. Если формула неоднозначна — запросить supplementary/issue, затем сделать **одну или несколько ясно подписанных интерпретаций**, не называя их точной авторской реализацией.
6. **Проверка.** Юнит-тесты нормировки/устойчивости весов, MMD (включая identical-distribution smoke), того, что meta-test является source, применения feature masking, стабильности по seed, поведения при малом числе источников, binary/multiclass API по подтверждению.
7. **Ablation.** Отдельные компоненты `RF ensemble only`, `meta-test weighting only`, `MMD only`, `feature masking only` и `full method` — если они корректно реализованы. Контроль вычислительной цены: matched total trees / fit time RF.
8. **Проверка репликации.** По возможности авторский glucose-monitoring пример или доступный ACS/TableShift с независимым **source-only** протоколом. Не выбирать meta hyperparams по целевым score, даже если так могло быть в исходной статье.
9. **Доказательства.** Отчёт `docs/methods/meta_forests_replication.md`: подтверждённые и неустановленные формулы, версия, тесты, результаты, статус достоверности; если blocked — исчерпывающий и конкретный blockers log.

### Независимая реализация не означает «новый метод»

Переход от алгоритма статьи к инженерной версии допускается, если правило оптимизации сохраняется. Любые научные изменения (новый штраф, недокументированная оптимизация objective, иное правило обучающих сред) должны оформляться как **отдельная интерпретация/вариант**, а не как установленная репликация. У каждого метода сохранять reference implementation baseline, а для внешних движков — paired baseline.

## Дополнительные методы

Time Robust Forest: самостоятельный RF-классификатор с временно-инвариантными split criteria, не просто одно дерево. MixMax: алгоритм выбора смеси известных групп для XGBoost; оригинальный benchmark worst-group, собственную строгую DG оценку отделить. Tree DRO: не полагаться на строку `kind='regression'` без проверки формул user-defined gradients. DIRF/O-IRF/HO-IRF, MIT IDT — ценные для научного контроля новизны и механики, но **не обязаны задерживать эксперименты шести основных** при недоступности полных формул.
