# Датасеты и DG-протоколы — краткая выжимка из отчёта, присланного пользователем

**Статус:** составлено по тексту отчёта в беседе от 04.11.2026; **это не отдельный оригинальный полный файл**. Основные цифры и ссылки необходимо сверять с официальными наборами при P0. Сюда включена практическая информация, влияющая на стенд.

## Содержание предыдущего исследования

- **TableShift:** 15 табличных бинарных задач; не все дают несколько исходных доменов. Для strict DG значимы многодоменные случаи, среди них Hospital Readmission (admission source, 21 категорий, выделен «emergency room»), ASSISTments (schools), ACS-derived задачи. Для пилота предпочтительны общедоступные данные.
- **Folktables/ACS:** публичные классификационные задачи по переписи, домены штаты/регионы и годы. Доступны естественные spatial/temporal splits. Строгий протокол требует фиксированных source/target states до просмотра target.
- **WhyShift:** полезен для анализа реальных механизмов `P(X)` и `P(Y|X)`; многие опубликованные настройки — один source → один target и не подходят без изменения для методов, требующих нескольких train domains.
- **Shifts Weather:** задачи регрессии температуры и многоклассовой классификации осадков; 123 метеопризнака, климат+время; официально **10 млн строк полного массива**. Нельзя отождествлять полную версию с каноническими train/dev/eval subsets.
- **Shifts Vessel Power/Wild-Tab:** регрессионные промышленные OOD-задачи, но доступность real Vessel/канонического evaluation требует отдельной проверки; Wild-Tab Weather и Shifts Weather не независимые источники данных.
- **TabReD:** 8 больших временных табличных задач; Cooking Time и Delivery ETA — регрессия. Официальные предобработанные данные содержат `x_meta.npy` и `splits/default`; этого недостаточно, чтобы автоматически считать их готовым multi-domain DG. Требуется аудит реальных timestamp, preprocessing и source eras.
- **Anchor Boosting ICU:** многобольничные DG-данные, высокая научная ценность, существенные ограничения доступа/вычислений; оставить резервом.
- **California Housing:** возможна лишь исследовательски заданная пространственная DG-схема; нет готового canonical multi-source domain split.
- **WILDS:** нативные image/text/graph задачи не использовать как основной табличный benchmark без дополнительного пайплайна признаков.

## Что было рекомендовано в полном тексте пользователя

- Классификация: TableShift многодоменный subset и Folktables, WhyShift как источник анализа shift mechanism.
- Регрессия: Shifts Weather, Vessel Power, Wild-Tab и отдельные задачи TabReD.
- Для нетемпоральных исходных сред: source-only LOEO/LODO.
- Для времени: forward-chaining, source-only tuning, никаких test-domain данных при early stopping.
- Не назначать типы covariate/label/concept shift только из наблюдаемого падения точности. Для реальных данных чаще корректен «mixed shift».
- Сравнивать не только среднюю метрику, но и качество на отдельных целевых доменах, computational cost, source-domain HPO. Использовать синтетику как дополнение, а не замену реальным наборам.
