# Перенос в четыре основные папки

Физическое разделение:

- `code/` — исходный код, тесты, конфигурации, окружение, локальные данные и журналы.
- `materials/` — документация, литература, исходные материалы и происхождение шаблонов.
- `nir/` — существующие результаты и новый редактируемый отчёт НИР.
- `vkr/` — отдельные будущие материалы ВКР.

`.git`, `.gitignore`, `.gitattributes`, README и файл workspace остаются техническими файлами общего корня. Git remote и история сохраняются.

## Проверка научной сохранности

`before.json` фиксирует предшествующий commit, старый/новый путь и SHA-256 каждого ранее отслеживаемого файла. `byte_preservation.json` подтверждает совпадение перенесённых байтов. Старый README сохранён как `README.before.md`; изменённые корневые `.gitignore`/`.gitattributes` перечислены явно. Исходные экспериментальные код, модели, данные, таблицы, frozen protocols и отчёты не исправляются этим переносом.

`code/bootstrap_workspace.py verify` проверяет frozen v2 runtime/packages/source pools, hashes frozen research documents и runtime hashes source/final протоколов v4. `tests_after_move.xml` содержит результат существующего набора тестов после переноса.

## Старые пути

Канонический физический корень runtime теперь `code/`. Исторические относительные имена внутри frozen manifests сохранены: `src/...`, `runs/...`, `reports/...`, `docs/...`. Bootstrap создаёт локальные представления `code/docs`, `code/reports`, `code/literature`, `code/research_input`, направленные на единственные физические папки. Они не копируются в Git и восстанавливаются после clone.

Исторические команды выполняются из `code/`. Для просмотра архивного HTML со старыми относительными cross-links его можно открывать через `code/reports/...`; актуальный навигатор расположен в `nir/index.html`. Оригинальные документы сохранены, включая их исторические ссылки. Неизменённая опубликованная структура также доступна по commit из `before.json`.

В новом LaTeX-отчёте ссылки на численные артефакты закреплены на существующем историческом commit. Новые отчёты и команды следует писать с каноническими четырьмя разделами.

Перенос не запускает переобучение и не переоткрывает target. Результаты v4 и прежних серий не становятся новым независимым экспериментом.
